# cf-rag-kit Implementation Plan

> **For agentic workers:** REQUIRED: Use superpowers:subagent-driven-development (if subagents available) or superpowers:executing-plans to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Create a new standalone pnpm monorepo `cf-rag-kit` by extracting and generalizing NobodyClimb's production RAG system into a reusable Cloudflare Workers template.

**Architecture:** The work is primarily extraction + generification — most files are copied from `~/Projects/nobodyclimb/` and modified to remove climbing-specific logic. New work includes: fetch-based api-client, 2 new UI trace visualizers, seed data, and demo app wiring.

**Tech Stack:** Cloudflare Workers + Hono 4, D1 (SQLite), Vectorize, Workers AI, Next.js 15, React 19, TailwindCSS, pnpm workspaces, Turborepo, TypeScript, Vitest

**Source repo:** `~/Projects/nobodyclimb/`
**Target repo:** `~/Projects/cf-rag-kit/` (new repo, initialized in Task 1)

- [ ] **Step 2: Create `seed/seed.ts`**

Note: The seed script runs directly against D1 and Vectorize via Wrangler bindings — it does NOT go through the HTTP API (there is no `/admin/ai/index` HTTP endpoint). Use `wrangler d1 execute` for D1 inserts and call the `IndexingService` via a Wrangler script for Vectorize.

The seed approach is two-phase:
1. Insert document rows into D1 via `wrangler d1 execute`
2. Run a Wrangler script that calls `IndexingService.reindexAll()` to generate embeddings

Create `seed/seed.ts` as a Wrangler script entry point:

```typescript
import { readFileSync } from 'fs'
import { execSync } from 'child_process'

const docs = JSON.parse(readFileSync('./seed/demo-documents.json', 'utf-8'))

async function seed() {
  console.log('🌱 Seeding cf-rag-kit demo...')

  // Phase 1: Run D1 migrations
  console.log('📦 Running migrations...')
  execSync('cd backend && pnpm db:migrate', { stdio: 'inherit' })

  // Phase 2: Insert seed documents into D1
  console.log(`📄 Inserting ${docs.length} documents into D1...`)
  for (const doc of docs) {
    const sql = `INSERT OR IGNORE INTO documents (id, title, content, category, tags, popularity_score, url, created_at) VALUES ('${doc.id}', '${doc.title.replace(/'/g, "''")}', '${doc.content.replace(/'/g, "''")}', '${doc.category}', '${JSON.stringify(doc.tags)}', ${doc.popularity_score}, '${doc.url}', datetime('now'))`
    execSync(`cd backend && wrangler d1 execute cf-rag-kit-db --local --command="${sql}"`, { stdio: 'pipe' })
  }
  console.log('✅ Documents inserted into D1')

  // Phase 3: Generate embeddings via backend indexing endpoint
  // Start backend first: pnpm dev:backend
  console.log('🔍 Generating embeddings (backend must be running on :8787)...')
  const res = await fetch('http://localhost:8787/api/v1/ai/index', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json', Authorization: `Bearer ${process.env.SEED_ADMIN_JWT}` },
    body: JSON.stringify({ type: 'document' }),
  })
  if (!res.ok) throw new Error(`Embedding failed: ${await res.text()}`)
  console.log('✅ Embeddings generated')

  console.log('\n🎉 Seed complete!')
  console.log('   Chat demo: http://localhost:3000/demo')
  console.log('   Admin:     http://localhost:3000/admin/ai')
}

seed().catch(console.error)
```

Note: The `POST /api/v1/ai/index` user-facing endpoint (not admin) triggers indexing. Verify this endpoint exists after Task 12; if not, trigger indexing directly via `wrangler d1 execute` + a separate Wrangler script.
