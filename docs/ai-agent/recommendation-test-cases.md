# 路線推薦系統測試案例

測試目標：驗證修復後的推薦系統不會推薦已完攀路線，且 Judge 能正確偵測約束違反。

對應 change：`openspec/changes/fix-recommendation-already-climbed/`

---

## 手動測試方法

1. 登入有完攀紀錄的帳號（或直接在 AI chat 貼查詢字串）
2. 觀察 pipeline trace 的 MMR 候選集是否包含已完攀路線
3. 觀察最終回答是否包含已完攀路線名稱
4. 觀察 Judge trace 的 `constraint_ok` 值

---

## TC-REC-01：原始 Bug 復現（最高優先）

**背景**：這是觸發 Bug 的真實案例，修復後此案例必須通過。

**完攀紀錄輸入**：
```
白虎（5.11d）、閃電（5.12a）、看起來我可以（5.11c）、泡泡龍（5.11b）、新竹客家人（5.10d）
```

**修復前產生的查詢字串**（舊行為，應已廢棄）：
```
我最近完攀了：白虎（5.11d）、閃電（5.12a）、看起來我可以（5.11c）、泡泡龍（5.11b）、新竹客家人（5.10d）。請推薦 3 條我尚未爬過、適合下一步挑戰的路線，難度可以稍高一級或類型不同。
```

**修復後預期查詢字串**（新行為）：
```
我的攀登程度約 5.12a，請推薦難度在 5.12b–5.12c 的運攀路線，或難度相近但類型不同的路線（傳攀 / 抱石）。
```
> 驗證重點：查詢字串中**不得出現**「白虎」「閃電」「看起來我可以」「泡泡龍」「新竹客家人」任何一個名稱。

**MMR 候選集驗證**（pipeline trace）：
- 閃電 **不應**出現在 MMR 選出的 5 筆中
- 泡泡龍 **不應**出現在 MMR 選出的 5 筆中
- 新竹客家人 **不應**出現在 MMR 選出的 5 筆中

**最終回答必須滿足**：
- 回答中推薦的路線名稱，不包含：白虎、閃電、看起來我可以、泡泡龍、新竹客家人

**理想回答範例**（推薦路線應為以下任意 3 條）：

| 路線名稱 | 難度 | 岩場 | 說明 |
|---------|------|------|------|
| 奇爬 | 5.12b | 墾丁 陽光牆 | 難度適當，有影片參考 |
| 投奔大陸 | 5.12a | 關子嶺 | 與使用者現有程度接近，不同岩場 |
| 野地飛鼠 | 5.12a / 5.12c | 關子嶺 | 關子嶺熱門路線 |
| 跳島戰術 | 5.12b | 墾丁 | 墾丁進階路線 |
| 陽光男孩 | 5.12b | 墾丁 | 類型相似，難度稍高 |

## TC-JUDGE-01：Judge 偵測約束違反

**目的**：驗證 Judge 的 `constraint_ok` 維度能正確識別「推薦了已完攀路線」的壞回答。

**測試方式**：直接呼叫 `runJudge()` 或在 pipeline debug 模式中注入以下壞回答，觀察 Judge 輸出。

**輸入 Query**：
```
我最近完攀了：白虎（5.11d）、閃電（5.12a）。請推薦 3 條我尚未爬過的路線。
```

**注入的壞回答**（模擬修復前的錯誤輸出）：
```
根據你的完攀紀錄，你目前攀登程度約為 5.11d。以下推薦三條路線：

1. 閃電（5.12a，運攀，墾丁陽光牆）：這條路線是墾丁陽光牆的經典路線，技巧性強。

2. 奇爬（5.12b，運攀，墾丁陽光牆）：下半段有小難關，可挑戰動態動作。

3. 白虎（5.11d，運攀，關子嶺）：不同岩場風格，值得體驗。
```

**預期 Judge 輸出**：
```json
{"groundedness": 1.0, "quality": 1, "constraint_ok": false}
```

**驗證重點**：
- `constraint_ok` 必須為 `false`（回答包含已完攀路線「閃電」和「白虎」）
- `quality` 必須強制為 `1`（即使 groundedness 高）

## TC-JUDGE-02：Judge 正確回答不扣分

**目的**：確保修改 Judge prompt 後，正確回答不被誤判。

**輸入 Query**：
```
我最近完攀了：白虎（5.11d）、閃電（5.12a）。請推薦 3 條我尚未爬過的路線。
```

**注入的好回答**：
```
根據你的攀登程度（5.12a），以下推薦三條進階路線：

1. 奇爬（5.12b，運攀，墾丁陽光牆）：難度稍高，下半段有技術性難關。

2. 投奔大陸（5.12a，運攀，關子嶺）：不同岩場風格，石灰岩感受與墾丁不同。

3. 野地飛鼠（5.12a，運攀，關子嶺）：關子嶺熱門路線，有多支影片可參考。
```

**預期 Judge 輸出**：
```json
{"groundedness": 1.0, "quality": 4, "constraint_ok": true}
```

**驗證重點**：
- `constraint_ok` 為 `true`（奇爬、投奔大陸、野地飛鼠均不在已完攀清單中）
- `quality` 維持 4 分

## 自動化測試建議

可在 `backend/tests/` 擴充現有 golden test set，加入以下類型的 test case：

```json
{
  "id": "REC-001",
  "type": "recommendation",
  "climbed_routes": ["白虎", "閃電", "看起來我可以", "泡泡龍", "新竹客家人"],
  "climbed_route_ids": ["<route_id_1>", "<route_id_2>", "..."],
  "expected_query_excludes": ["白虎", "閃電", "看起來我可以", "泡泡龍", "新竹客家人"],
  "expected_answer_excludes": ["白虎", "閃電", "看起來我可以", "泡泡龍", "新竹客家人"],
  "ci": false
}
```

> 注意：自動化需要真實的 `route_id`，需從 DB 查詢後填入。建議先手動測試確認後，再加入 CI。
