## ADDED Requirements

### Requirement: 個人頁面「推薦」Tab
個人資料頁 SHALL 新增「推薦」Tab，顯示用戶的 AI 路線推薦歷史，預設顯示最新一筆，底部支援載入更多。

#### Scenario: 有推薦記錄時顯示最新推薦
- **WHEN** 已登入用戶進入個人頁面並切換到「推薦」Tab
- **THEN** 顯示最新一筆推薦的 `answer` 文字及 `sources` 路線卡片（複用 `SourceCard` 元件），並顯示觸發方式（系統/手動）與時間

#### Scenario: 無推薦記錄時的空狀態
- **WHEN** 用戶的推薦歷史為空
- **THEN** 顯示「完成第一筆完攀後，AI 將為你推薦下一條路線」的引導文案，不顯示任何推薦卡片

#### Scenario: 推薦生成中的等待狀態
- **WHEN** 推薦歷史為空且用戶剛完成完攀（距最新完攀 < 30 秒）
- **THEN** 顯示骨架屏與「推薦生成中...」提示，前端每 2 秒 polling 一次（最多 3 次）後放棄

#### Scenario: 載入更多歷史推薦
- **WHEN** 用戶點擊「載入更多」按鈕
- **THEN** 以分頁（`offset += 10`）向後端請求更多推薦，追加至現有列表底部

#### Scenario: 手動重新推薦
- **WHEN** 用戶點擊「重新推薦」按鈕，且配額充足
- **THEN** 呼叫 `POST /api/v1/ai/recommendations`，成功後在列表頂部顯示新推薦，並更新 AI 配額顯示

#### Scenario: 手動重新推薦配額不足
- **WHEN** 用戶點擊「重新推薦」按鈕，但配額已耗盡
- **THEN** 顯示 Toast 通知「今日 AI 配額已用完，明日重置」，不發送請求

---

### Requirement: 完攀確認頁 inline 推薦引導
完攀紀錄確認成功後，前端 SHALL 根據本地狀態（是否為當日前 3 次完攀）決定是否顯示推薦引導訊息，不依賴 ascent API 回應欄位。引導訊息 SHALL 引導用戶至個人頁面「推薦」Tab 查看。

#### Scenario: 完攀成功後顯示推薦引導（推薦生成中）
- **WHEN** 用戶成功新增完攀紀錄，且前端記錄的當日系統觸發次數未達 3 次（以 session storage 暫存計數）
- **THEN** 完攀確認頁底部顯示「AI 正在為你推薦下一條路線，稍後至個人頁面查看」，附「前往查看」連結導向推薦 Tab；前端將本地計數遞增

#### Scenario: 推薦 Tab 顯示路線卡片
- **WHEN** 推薦生成完成，用戶進入「推薦」Tab
- **THEN** 顯示推薦的 `answer` 說明文字（LLM 生成），以及每條推薦路線的 `SourceCard`（包含路線名稱、難度、岩場名稱、路線連結），並顯示「根據你的 N 條完攀紀錄推薦」的 context 說明

#### Scenario: 當日推薦引導次數達上限
- **WHEN** 用戶成功新增完攀紀錄，但前端本地當日計數已達 3 次
- **THEN** 完攀確認頁不顯示推薦引導訊息，正常顯示完攀結果
