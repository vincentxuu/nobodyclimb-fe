## 新增需求

### 需求：單一文字 embedding 生成
系統應能使用 `@cf/baai/bge-m3` 模型為單一文字輸入生成 1024 維度的向量 embedding。

#### 場景：為路線描述生成 embedding
- **當** 服務收到文字字串（例如「龍洞 5.10a 運動攀登路線」）
- **則** 服務回傳代表語義向量的 1024 元素浮點數陣列

#### 場景：處理空白文字輸入
- **當** 服務收到空字串
- **則** 服務回傳錯誤，指出輸入無效

### 需求：批次文字 embedding 生成
系統應支援批次處理多個文字轉為 embeddings，每次請求最多 100 個文字。

#### 場景：為多條路線生成 embeddings
- **當** 服務收到包含 50 個文字字串的陣列
- **則** 服務回傳 50 個對應的 1024 維向量陣列，順序相同

#### 場景：批次大小超過限制
- **當** 服務收到超過 100 個文字的單一批次
- **則** 服務自動分割為多次 API 呼叫並回傳所有結果

#### 場景：處理部分批次失敗
- **當** 批次中有一個文字無法轉為 embedding
- **則** 服務記錄錯誤並繼續處理剩餘文字

### 需求：繁體中文語言支援
系統應使用 BGE-M3 模型，為繁體中文文字（包含攀岩術語）提供最佳化的 embeddings。

#### 場景：轉換中文路線名稱
- **當** 服務轉換「黃色乖乖」（一個中文路線名稱）
- **則** 產生的 embedding 能捕捉到與其英文等價物相當的語義意義

#### 場景：轉換混合語言內容
- **當** 服務轉換包含中英文的文字（例如「龍洞 Yellow Wall 5.10a」）
- **則** 服務產生包含兩種語言的有效 embedding

### 需求：一致的 embedding 維度
系統應始終產生正好 1024 維度的 embeddings，與 Vectorize 索引設定相符。

#### 場景：驗證 embedding 維度
- **當** 任何文字被轉換為 embedding
- **則** 產生的向量正好有 1024 個元素

### 需求：Workers AI 整合
系統應使用 `AI` binding 整合 Cloudflare Workers AI 來執行 embedding 模型推論。

#### 場景：呼叫 Workers AI API
- **當** embedding 服務被呼叫
- **則** 服務呼叫 `env.AI.run('@cf/baai/bge-m3', { text: [...] })`

#### 場景：處理 Workers AI 不可用
- **當** Workers AI 服務不可用或回傳錯誤
- **則** 服務拋出適當的錯誤，包含除錯用的上下文資訊
